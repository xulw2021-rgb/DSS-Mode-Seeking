# DSS-Mode-Seeking

**Mode-Seeking Kernel Losses for Robust Distribution System State Estimation: Contamination-Stability Theory and Cross-System Evidence**

This repository accompanies the Axioms submission of the same title by Yi Lin, Dingfei Que, and Liwen Xu (corresponding author: xulw@ncut.edu.cn).

## Key idea

Learning-based distribution system state estimation (DSSE) predictors are usually trained with squared or WLS-shaped objectives. A quadratic objective estimates the conditional mean of the state and has an unbounded score, so contaminated measurements can dominate training. This work replaces the squared objective with the Gaussian kernel modal loss

L_b(r) = 1 − exp(−r²/(2b²)),

whose score is bounded and redescending. At finite bandwidth the population target is a Gaussian-smoothed mode of the conditional state distribution, and as b → 0 the population minimizer converges to the conditional mode. The loss is bounded in [0,1], which underlies a clean-risk stability guarantee for training-distribution contamination (excess risk 2ε_c + 4Γ_n), alongside Rademacher generalization bounds and an SGD convergence result.

The empirical study uses a corrected, seed-disciplined protocol (five independent training runs per cell, train-only normalization, paired test-corruption realizations, paired-bootstrap intervals). The modal-loss MLP attains significantly lower voltage RMSE than its squared-loss counterpart at every tested condition on four systems (CIGRE-14, IEEE-30, Oberrhein-70, and the independently generated PanTaGruEl IEEE-14 benchmark). In the robust-loss family comparison, no statistically detectable modal–Tukey difference was found under the tested frozen configuration; the modal loss is competitive with the strongest conventional robust baseline tested rather than universally superior to it. The GNN advantage is architecture/system dependent, and the optimization-based Modal-WLS solver retains initialization-sensitive convergence under severe contamination (analyzed with multi-start).

## Repository structure

```
src/          validated implementation modules (losses, models, solvers, data pipeline, framework)
scripts/      experiment runners, data converters, publication-artifact generation
configs/      frozen experiment configurations
results/final frozen corrected results used by the manuscript tables/figures
tables/publication/   generated manuscript tables (LaTeX + CSV)
figures/publication/  generated manuscript figures (PDF)
tests/        lightweight correctness tests (no training required)
docs/         reproducibility, datasets, experiment map, reproduction maps
```

## Installation

### Conda (validated environment)

Validated on Linux (kernel 5.15), Python 3.10.0, PyTorch 2.1.2+cu121, pandapower 2.14.10, with NVIDIA GPUs (2× RTX 4090 used for training).

```bash
conda env create -f environment.yml
conda activate dsse-modal
```

### pip

```bash
pip install -r requirements.txt   # torch with CUDA support must be installed per the PyTorch index
```

## Quick start (no training, no GPU)

```bash
pytest tests/ -q
python scripts/reproduce_publication_artifacts.py
python scripts/verify_publication_artifacts.py
```

The first command runs the lightweight correctness tests; the second regenerates Tables 2–7 and Figures 1–5 from the frozen results in `results/final/`; the third verifies the regenerated artifacts match the packaged publication artifacts.

## Reproduce paper tables and figures

```bash
python scripts/reproduce_publication_artifacts.py   # outputs to reproduced/tables, reproduced/figures
python scripts/verify_publication_artifacts.py      # numeric comparison vs tables/publication
```

No training is required: the tables and figures read the frozen corrected results directly.

## Reproduce experiments

Full experiment commands (training, seeds, devices, expected compute) are documented in [docs/REPRODUCIBILITY.md](docs/REPRODUCIBILITY.md). In brief:

- generate simulation data with `python scripts/generate_ieee30_data.py` (IEEE-30) and `python src/toy_network.py`-equivalent flows for the distribution grids (see docs),
- download and convert the PanTaGruEl benchmark (see docs/DATASETS.md),
- run the per-experiment runners from the repository root with explicit `--device`, seeds, and output directories.

- Tables/figures reproduction: CPU, minutes.
- Full neural experiments: GPU recommended; the paper's experiments used 5 independent training runs per cell (see docs/REPRODUCIBILITY.md for per-experiment estimates).

## Reproducibility notes

- The paper reports five independent training runs per cell; 10,000 bootstrap resamples do not increase this replication level.
- All normalization statistics are fitted on the training partition only.
- PanTaGruEl is an independently generated external benchmark (Level 3), not field measurement data.
- GPU nondeterminism: the protocol is statistically reproducible, not bitwise deterministic across GPU architectures.
